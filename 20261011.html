SWOT分析の罠
その「強み」は、いずれ最大の弱点になる
今日の評価：
🤔 世間の常識
SWOT分析は強み・弱み・機会・脅威を整理して戦略を立てるフレームワークだ
💥 実は違う
ハーバード経営大学院のドロシー・レナード＝バートンは、かつての強みが硬直化し組織を縛り続ける現象を「コア・リジディティ（Core Rigidity）」と呼んだ。SWOTで強みを先に書く行為自体が、その強みを『動かせない前提』として固定してしまう
強みから始めると「今持っているものを活かす」発想に固定される。市場は変化するので、10年前の強みが今の強みとは限らない。外部環境（O/T）を先に読み、『この機会に誰より早く乗れる強みは何か』を逆算すれば、今の強みの中で何を手放すべきかまで見えてくる
プロの行動
SWOTを書く前に「3年後に最も大きい機会はどこか」を先に1枚書く。次に『今の強みのうち、その機会到達の邪魔をしているものはどれか』を1つ挙げる。その後でSWOT分析を逆引きで埋める
今日試すプロンプト
私の事業のSWOT分析を機会（O）起点で設計してください。 事業概要：[事業内容・対象市場・現在の規模] Step1：この市場で今後3年間で最も大きな機会を3つ特定する Step2：各機会に対して「乗るために必要な強み」を定義する Step3：現在の自社の強みとのギャップを分析する Step4：最も有望な機会×最小のギャップの組み合わせを推薦する
「強みは資産であり、同時に負債になる。SWOTはその両面を見せない」

AIフロント
Extended thinkingのON/OFFを呼び出し間で切り替えると、それだけでプロンプトキャッシュが丸ごと壊れる
キャッシュ設計はthinking設定の一貫性とセット
今日の評価：
😓 なぜ上手くいかないか
同じシステムプロンプト・同じ参考資料を使い回しているのに、リクエストによってextended thinkingを有効にしたり、budget_tokensの値を変えたりする。プロンプトキャッシュはリクエスト構造（thinking設定を含む）の一致が前提のため、この変更だけでキャッシュされたprefixが無効化され、以降の呼び出しは毎回フルプライスで再計算される。エラーは出ないため、コストが跳ね上がっていること自体に気づかない
🧠 プロが無意識にやっていること
自動化スクリプト・繰り返し呼び出す処理では、thinking設定（有効/無効・budget_tokensの値）をリクエストごとに変えず固定する。タスクによってthinkingの要否が違う場合は、『同じ呼び出し内で条件分岐させる』のではなく、thinking設定ごとに呼び出し系統そのものを最初から分離し、キャッシュしたい共通部分（システムプロンプト・参考資料）は変化しない系統側にまとめる
改善プロンプト
# 悪い例: 共通system promptを使い回しつつthinking設定だけ可変 resp = client.messages.create( model=MODEL, system=SHARED_SYSTEM_PROMPT, thinking=({"type": "enabled", "budget_tokens": b} if need_thinking else None), messages=messages) # 良い例: thinking設定ごとに呼び出し系統を固定して分離 STANDARD_CALL = lambda msgs: client.messages.create( model=MODEL, system=SHARED_SYSTEM_PROMPT, messages=msgs) DEEP_CALL = lambda msgs: client.messages.create( model=MODEL, system=SHARED_SYSTEM_PROMPT, thinking={"type": "enabled", "budget_tokens": 2048}, messages=msgs)
期待される出力
同一パイプラインでのキャッシュヒット率が安定し、気づかれないままのコスト増が発生しない状態
「エラーにならないコスト増ほど、誰も気づかないまま積み上がる」

分散投資とポジションサイズ
1銘柄に資金を集中させず、複数銘柄・複数資産に分けることでリスクを抑える考え方。『いくら分散するか』と同じくらい『1銘柄にどれだけ資金を入れるか（ポジションサイズ）』が重要。
100万円を1銘柄に集中させると、その銘柄が20%下落すれば20万円の損失。同額を5銘柄に分けていれば、1銘柄が20%下落しても全体では4%の下落で済む。
使い方
『注目候補』が複数示されているのは、視点の異なる候補を並べて比較検討してもらうため。全部に同じ金額を張るのではなく、自分の許容リスクに応じて配分を変える。
📈 株トピックとの繋がり
注目候補を『これが一番良さそう』と1つに絞るのではなく、リスクの異なる候補を組み合わせて見る使い方が想定されている。

CEP（カテゴリーエントリーポイント）と想起集合
顧客が「〜のときに何を買おう」と考える入口（CEP）ごとに、頭に浮かぶブランドの集合（想起集合）は異なる。この集合に入っていないブランドは、比較検討の土俵にすら乗らない。バイロン・シャープらエビデンス派マーケティングの中核概念。
「金曜の夜、頑張った自分へのご褒美」というCEPで想起されるアイス（ハーゲンダッツ）と、「子どものおやつ」で想起されるアイスは別物。同じ人の頭の中でも、状況が変われば想起されるブランドは入れ替わる。
使い方
自社ブランドが「どのCEPで想起されているか／されていないか」を顧客インタビューで洗い出す。想起されていないCEPこそが、広告メッセージで開拓すべき伸びしろ。

ストックオプション
将来のあらかじめ決めた価格（権利行使価格）で自社株式を取得できる権利を、役員・従業員に付与する制度。現金報酬を抑えつつ、株価上昇による大きなリターンの可能性を提供することで、創業初期の人材確保・引き留めに使われる。付与時点では課税されず、行使・売却時に課税される税制適格ストックオプションの設計が実務上の争点になりやすい。
メルカリは上場前に幅広い従業員層にストックオプションを付与し、上場後に多くの『メルカリ長者』を生んだことで知られる。人材採用の場でも『上場した場合のアップサイド』を採用条件の一部として明示的に使えた事例。
使い方
初期メンバーへの付与だけで満足せず、税制適格要件（発行会社の要件・権利行使価格等）を満たしているかを必ず専門家に確認する。要件を外れると行使時に給与課税されるなど従業員側の税負担が跳ね上がり、せっかくの制度が『もらって損した』という不満に変わることがある。

ストーリーテリング3公式（Marketing 7.0応用編）
Marketing 7.0の第三部「応用」では、ブランドストーリーは装飾的なコミュニケーションではなく「顧客の心（マインド）への構造化された道筋」だと再定義し、3つのストーリーテリング公式を提示する：①注意→決断（Attention-Decision）②対立→解決（Conflict-Resolution）③痛み→利得（Pain-Gain）。

使い方

使い方
